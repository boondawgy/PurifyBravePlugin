Implement a read-only movie status API for the Purify for Plex browser extension. Inspect Purifier's existing API and data models first and preserve the existing POST /media contract ({file_path, profile: "Movie", title}, response queued: true).

The extension needs to discover movies previously submitted from any client and distinguish queued, processing, completed, and failed. Local extension history currently means only "sent", not completed.

Provide a documented GET endpoint (suggest GET /media/status) returning application/json with a versioned envelope, paginated items, and a next cursor. Each item should include the stable media/job ID, canonical file_path in Purifier's path namespace, media type, title, profile, normalized processing status, and updated_at (UTC ISO 8601). Include error details suitable for display if available, without secrets. Define how multiple jobs for the same file are represented, including retries and which job is authoritative. Return an empty list for an empty database, not an error. Document pagination consistency and status definitions, especially what completed guarantees.

Matching must use the exact canonical file path after the extension's configured prefix mapping; title alone is not a reliable identity. Explain path normalization and server-side mappings, and expose submitted file_path as well if canonicalization changes it. If Plex server machineIdentifier and ratingKey can already be retained, include them as optional matching fields, but don't require them for existing records or change the required POST fields.

Support bounded batch lookup by submitted file paths if practical, to avoid downloading the full media history for each page. Document the exact method, URL/body, limits, and missing-path behavior. Reuse existing authentication and explain the headers a browser extension must send. Keep this read-only and do not expose Plex tokens or credentials. Include tests appropriate to your existing test suite.

Return integration instructions for the extension developer: exact endpoint(s), authentication, query/body examples, response examples for all states and errors, pagination, recommended polling interval, and how duplicates/retries/path mappings are handled. Do not claim the extension integration is done; it will be implemented separately once this contract is returned.

Refresh policy: the extension should default to one automatic status sync per 24 hours, with a durable cached snapshot shared by tabs. Users can disable automatic refresh, set a custom interval in hours, and manually refresh from settings regardless of the automatic setting. Opening a library or returning to a tab should reuse the cache; only refresh if enabled and the cache is due. New posters should match against the cached snapshot without triggering a full sync. A successful POST /media should update its local indicator immediately. Deduplicate overlapping automatic/manual syncs across tabs. Failed syncs must keep the last successful snapshot and timestamp, report the error, and avoid rapid retries. Please design the endpoint for this daily snapshot approach and document pagination so the extension can commit a complete snapshot atomically.
